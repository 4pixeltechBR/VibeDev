## 🇺🇸 English

**Release date:** 2026-07-26
**Scope:** VibeDev v1.9.0
**Type:** Minor — additions only. Backward compatible.
**VibeShield version:** unchanged (v2.0.0)
**Inspired by:** Dante Testa — Prompt Mestre WordPress v1.14.0 (jul/2026)

This release closes the 3 governance gaps identified after v3.7.0: **provenance** (who made this file?), **pre-mortem** (what could go wrong?), and **onboarding** (how do I use this?).

### What's in this release

#### 1. Authorship signature (Feature 1)

`vibedev/references/autoria-arquivos.md` + bloco `## Autoria` in 3 templates.

If you fill in the `## Autoria` block in `PROJECT_STATE.md` with `Incluir header de assinatura nos arquivos: [x] sim`, every new file generated by the agent gets an authorship header at the top. The header adapts to the language (PHP gets `//`, Python gets `#`, HTML gets `<!-- -->`, etc).

If left empty, **zero behavior change** — no header, no companion file, nothing.

**Why it matters:** LGPD Art. 37 (Brazil) and EU AI Act Art. 12 (Europe) require traceability of AI-generated artifacts. Open-source alternative to commercial products.

#### 2. Devil's Advocate gate in `/vd-plan` (Feature 2)

`vibedev/commands/vd-devils-advocate.md`.

When `/vd-plan` is run, after Red Team and before estimation, a **mandatory pre-mortem** triggers. The agent produces:
- Top 3 risks (probability × impact)
- 1 internal contradiction between user intent and `PROJECT_STATE`
- 1 blind angle nobody mentioned

The agent **cannot proceed** without explicit user response on all 5 items. Opt-out via `--skip-devils-advocate` (auto-skipped for trivial decisions).

**Why it matters:** Gary Klein (HBR 2007) shows that pre-mortems reduce project failures by 30%. Atul Gawande (2009) shows that simple checklists prevent catastrophic errors. Together: a small cost for big safety.

#### 3. Auto `MANUAL.md` in `/vd-close` (Feature 3)

`vibedev/commands/vd-manual.md`.

When `/vd-close` is run, after compaction and before final confirmation, a **`MANUAL.md` is generated/updated** at the project root with 5 sections:
- Overview (1 paragraph)
- How to run (commands)
- How to use (user flows)
- How to extend (where to touch to add feature X)
- Troubleshooting (3+ common problems + solution)

Adapts to `modo_usuario`: layman mode uses plain language, no absolute paths, no jargon. Technical mode uses paths, classes, functions, diagrams. Custom sections are preserved if `MANUAL.md` already exists.

Opt-out via `--no-manual`.

**Why it matters:** Reduces onboarding cost dramatically. A new contributor (or future you) can `cat MANUAL.md` and have everything needed to run, use, and extend the project.

#### 4. ADR 0010

`.agents/adr/0010-v3-8-orquestracao-camadas.md` — documents context, decision, consequences, and rejected alternatives for the 3 features.

### Backward compatibility

- 100% backward compatible. No existing project breaks.
- 12 commands unchanged. New behaviors are gates with opt-out flags.
- Templates of `PROJECT_STATE.md` grow ~10 lines (the `## Autoria` block). Projects that don't fill it have zero impact.

### What's next

- **v3.9.0 (TBD):** Performance budget per project (Core Web Vitals-inspired metrics for non-web projects).
- **v3.9.x (TBD):** `vd-status` v2 with visual map of project state.

`vibedev/commands/vd-devils-advocate.md`.

Quando `/vd-plan` roda, depois do Red Team e antes da estimativa, um **pré-mortem obrigatório** dispara. O agente produz:

**Por que importa:** Gary Klein (HBR 2007) mostra que pré-mortens reduzem falhas de projeto em 30%. Atul Gawande (2009) mostra que checklists simples previnem erros catastróficos. Juntos: custo pequeno, segurança grande.

Quando `/vd-close` roda, depois da compactação e antes da confirmação final, um **`MANUAL.md` é gerado/atualizado** na raiz do projeto com 5 seções:
