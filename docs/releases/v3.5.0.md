## 🇺🇸 English

**Release date:** 2026-07-24
**Scope:** VibeDev core (v1.6.0)
**Type:** Minor — additions only, no behavior change to existing commands.

### What changed

This release borrows **structural patterns** from [mattpocock/skills](https://github.com/mattpocock/skills) — a competing project by Matt Pocock (creator of Total TypeScript). His project explicitly argues *against* "vibe coding" frameworks like VibeDev. We don't agree philosophically, but his **engineering hygiene** is empirically useful. We adopted what serves our audience, rejected what conflicts, and documented both transparently.

The result: VibeDev now has the **router, the discipline, and the clarity** that mature frameworks need — without changing how it works for the layman user.

### What's in this release

#### 1. `/vd-help` — Router command

New file `vibedev/commands/vd-help.md`. Inspired by `ask-matt` in Pocock's project, but adapted for our leigo audience.

The router shows:
- **Mental map** of the normal cycle (spark → start → status → plan → build → check → ...)
- **Commands per project phase** (1-8 of the VibeDev lifecycle)
- **Commands per emotional situation** (energized, exhausted, confused, anxious, stuck, frustrated)
- **One-line summary** of the main flow
- **Emergency command**: `/vd-kill` always available

User-invoked only. The model never auto-fires this. The leigo asks for help explicitly.

#### 2. `.agents/adr/` — 6 Architecture Decision Records

New directory with 6 ADRs covering our **past and current design decisions**:

| # | Decision | Rationale |
|---|---|---|
| 0001 | VibeDev is monolithic (1 SKILL.md) | Unified state for leigo, not 22 small skills |
| 0002 | Country Mode is one file with 12 sections | Easier maintenance, simpler release |
| 0003 | 2 modes (leigo + tecnico) | Clarity over granularity |
| 0004 | Anti-"tá" validation in /vd-check | Integrity over velocity |
| 0005 | Formal Sandeco citation via CREDITS.md | Traceability, recognition |
| 0006 | Model-invoked-anunciado (not silent) | Auditability for leigo |

Each ADR is dated, contextualized, immutable. If superseded, links to the new one.

#### 3. `.out-of-scope/` — 7 documents explaining what VibeDev does NOT do

New directory documenting things VibeDev **deliberately doesn't do**:

- `not-a-ci-cd-tool.md` — we govern projects, not deployments
- `not-for-monorepos.md` — one PROJECT_STATE.md per project
- `not-an-issue-tracker.md` — use GitHub Issues, Linear, or Jira
- `not-a-low-code-builder.md` — we assume you want to understand the code
- `not-replacement-for-vibeshield.md` — security audit is a separate skill
- `not-providing-stack-recommendations.md` — we present trade-offs, not endorsements
- `not-pretending-to-be-vibeshield.md` — we don't do security audits

Each file follows Pocock's pattern: what we do, what we don't, why, what to use instead.

#### 4. Invocation model in SKILL.md

New section in `vibedev/SKILL.md` explicitly classifying every command and silent rule:

- **User-invoked**: human types the command. Model never fires alone.
- **Model-invoked-anunciado**: model fires alone but **announces** in plain language and offers veto.

This is the **adaptation twist** from Pocock. He has user-invoked vs **silent** model-invoked. We chose announced because our leigo audience needs to see what the framework is doing — silent automation makes the framework a black box.

Table in SKILL.md shows the 11 commands + 7 silent rules, with their invocation type and the announcement template each uses.

#### 5. CREDITS.md update

Added [mattpocock/skills](https://github.com/mattpocock/skills) as a **competitive reference** (not academic citation, like Sandeco's paper). The entry explicitly lists:

- **What we adopted** (router pattern, ADRs, out-of-scope, invocation distinction) — each with how we adapted it
- **What we rejected** (plugin marketplace, npx install, bucketed skills, 22-skill composition) — each with why
- **Why we cite** (transparency beats silence — his project is a credible counter-position, useful to engage with openly)

### Backward compatibility

- All additions are **documentation** + 1 new command (`/vd-help`)
- No existing command changed behavior
- Invocation model change (silent → announced) is **transparent** to users: they get the same automation, just now they see it happening
- No data migration needed
- No config change needed

- **Sandeco Macedo** (arXiv:2607.00038) is **academic citation**: his paper materially influenced VibeDev's design via epistemic discipline and 5-level verification ladder. Cited as "Papers & academic work".

## 🇧🇷 Português

**Data do release:** 2026-07-24
**Escopo:** VibeDev core (v1.6.0)
**Tipo:** Minor — só adições, sem mudança de comportamento nos comandos existentes.

### O que mudou

Esse release pega emprestado **padrões estruturais** do [mattpocock/skills](https://github.com/mattpocock/skills) — projeto do Matt Pocock (criador do Total TypeScript). O projeto dele explicitamente argumenta *contra* frameworks "vibe coding" como o VibeDev. A gente não concorda filosoficamente, mas a **higiene de engenharia** dele é empiricamente útil. Adotamos o que serve nosso público, rejeitamos o que conflita, e documentamos os dois com transparência.

Resultado: VibeDev agora tem o **router, a disciplina, e a clareza** que frameworks maduros precisam — sem mudar como funciona pro usuário leigo.

### O que tem nesse release

#### 1. `/vd-help` — Comando router

Arquivo novo `vibedev/commands/vd-help.md`. Inspirado em `ask-matt` do projeto do Pocock, mas adaptado pro público leigo.

O router mostra:
- **Mapa mental** do ciclo normal (spark → start → status → plan → build → check → ...)
- **Comandos por fase do projeto** (1-8 do ciclo VibeDev)
- **Comandos por situação emocional** (animado, exausto, confuso, ansioso, travado, frustrado)
- **Resumo de 1 linha** do fluxo principal
- **Comando de emergência**: `/vd-kill` sempre disponível

User-invoked. Modelo nunca dispara sozinho. Leigo pede ajuda explicitamente.

#### 2. `.agents/adr/` — 6 Architecture Decision Records

Novo diretório com 6 ADRs cobrindo nossas **decisões passadas e atuais**:

| # | Decisão | Justificativa |
|---|---|---|
| 0001 | VibeDev é monolítica (1 SKILL.md) | Estado unificado pro leigo, não 22 skills |
| 0002 | Modo País é 1 arquivo com 12 seções | Manutenção mais fácil, release mais simples |
| 0003 | 2 modos (leigo + técnico) | Clareza > granularidade |
| 0004 | Validação anti-"tá" no /vd-check | Integridade > velocidade |
| 0005 | Citação formal Sandeco via CREDITS.md | Rastreabilidade, reconhecimento |
| 0006 | Model-invoked-anunciado (não silencioso) | Auditabilidade pro leigo |

Cada ADR é datado, contextualizado, imutável. Se substituído, linka pro novo.

#### 3. `.out-of-scope/` — 7 documentos explicando o que VibeDev NÃO faz

Novo diretório documentando coisas que VibeDev **deliberadamente não faz**:

- `not-a-ci-cd-tool.md` — governamos projetos, não deploys
- `not-for-monorepos.md` — 1 PROJECT_STATE.md por projeto
- `not-an-issue-tracker.md` — use GitHub Issues, Linear, ou Jira
- `not-a-low-code-builder.md` — assumimos que você quer entender o código
- `not-replacement-for-vibeshield.md` — auditoria de segurança é skill separada
- `not-providing-stack-recommendations.md` — apresentamos trade-offs, não endossos
- `not-pretending-to-be-vibeshield.md` — não fazemos auditoria de segurança

Cada arquivo segue o padrão do Pocock: o que fazemos, o que não, por quê, o que usar em vez.

#### 4. Modelo de invocação no SKILL.md

Nova seção em `vibedev/SKILL.md` classificando explicitamente cada comando e regra silenciosa:

- **User-invoked**: humano digita o comando. Modelo nunca dispara sozinho.
- **Model-invoked-anunciado**: modelo dispara sozinho mas **anuncia** em linguagem clara e dá chance de veto.

Essa é a **adaptação** do Pocock. Ele tem user-invoked vs model-invoked **silencioso**. A gente escolheu anunciado porque nosso público leigo precisa ver o que o framework tá fazendo — automação silenciosa faz o framework virar caixa-preta.

Tabela no SKILL.md mostra os 11 comandos + 7 regras silenciosas, com tipo de invocação e template de anúncio que cada um usa.

#### 5. CREDITS.md atualizado

Adicionado [mattpocock/skills](https://github.com/mattpocock/skills) como **referência competitiva** (não citação acadêmica como o paper do Sandeco). A entrada lista explicitamente:

- **O que adotamos** (router, ADRs, out-of-scope, distinção de invocação) — cada um com como adaptamos
- **O que rejeitamos** (plugin marketplace, install via npx, skills em buckets, 22 skills compostas) — cada um com por quê
- **Por que citamos** (transparência > silêncio — projeto dele é contra-posição credível, útil engajar abertamente)

### Compatibilidade

- Todas as adições são **documentação** + 1 comando novo (`/vd-help`)
- Nenhum comando existente mudou comportamento
- Mudança de invocação (silencioso → anunciado) é **transparente** pros usuários: recebem a mesma automação, só agora **vêem** quando rola
- Sem migração de dados
- Sem mudança de config
