## 🇺🇸 English

**Release date:** 2026-07-25
**Scope:** VibeDev v1.8.0
**Type:** Minor — additions only.

This release adds the **3rd satellite skill** to the VibeDev family: `/vd-arch-review`. Where VibeDev governs the project lifecycle and VibeShield audits security, **`/vd-arch-review` audits architecture** — the 3 holes left after v3.6.0 (layer separation, code anti-patterns, dep vs custom).

### What's in this release

#### 1. `/vd-arch-review` — 3rd satellite skill

`vibedev/commands/vd-arch-review.md`. User-invoked, for devs (not leigos).

**3 sub-commands mapping to 3 levels of depth** (inspired by Sandeco Macedo's 5-level verification ladder, arXiv:2607.00038):

| Sub-command | Levels | What it does |
|---|---|---|
| `/vd-arch-full` | 1+2+3 | Full audit: stack, architecture, health |
| `/vd-arch-only` | 2 | Architecture + components + critical flows |
| `/vd-arch-health` | 3 | Code health + technical debt |

**Categories of detection** (the 3 holes identified earlier):
- **Layer separation** — UI importing ORM, controller with SQL inline, etc.
- **Anti-patterns** — generic filenames (util.ts, helper.ts), god objects, fat controllers, hotspots
- **Abstraction leaks** — view knowing DB schema, business logic in routes
- **Coupling** — circular imports, fan-out > 20, god modules
- **Dep vs Custom** — underused libs (candidates for removal), custom code reinventing standard API
- **Test coverage** — hotspots without tests, critical paths untested
- **Documentation** — missing README, missing ARCH_MAP.md

**Vocabulary** from mattpocock/skills `codebase-design`:
- Module, interface, implementation, adapter, seam
- Deep vs shallow modules
- Leverage, locality

**State persistence:**
```
project/
├── ARCH_MAP.md                      # master document (Mermaid diagrams)
└── .arch-review/                    # subdir with detailed reports
    ├── SUMMARY.md                   # executive index
    ├── macro-stack.md               # level 1
    ├── meso-arch.md                 # level 2
    └── micro-health.md              # level 3
```

**Output format per finding:**
```markdown
### Finding [N]
- Category: Layers | Anti-pattern | Abstraction | Dep vs Custom | Convention | Test | Docs
- Severity: 🔴 blocker | 🟡 warning | 🔵 nit
- Location: path/to/file.ts:line-line
- Snippet: <2-3 line code>
- Problem: 1-2 sentence description
- Suggestion: how to fix
- Effort: 🟢 15min | 🟡 1h | 🔴 2h+
```

**Verdict:** OK / REVISAR / BLOQUEAR (same pattern as VibeShield)

#### 2. Reference prompts for each level

3 reference files with concrete checks per level:
- `vibedev/references/arch-review-macro.md` — stack/topology (bash commands, file lists)
- `vibedev/references/arch-review-meso.md` — architecture/flow (Mermaid, ERD, sequence diagrams)
- `vibedev/references/arch-review-micro.md` — health/debt (anti-patterns, coupling, dep vs custom, tests)

#### 3. Templates

- `vibedev/assets/ARCH_MAP-template.md` — master document template
- `vibedev/assets/arch-review-template.md` — subdir template with SUMMARY structure

#### 4. ADRs

- `.agents/adr/0008-vd-arch-review-skill.md` — why 3rd skill, why not absorbed by VibeShield or VibeDev core
- `.agents/adr/0009-arch-review-multi-nivel.md` — why 3 levels (not 1, 2, or 5)

#### 5. `.out-of-scope/not-an-arch-audit-tool.md`

Explicitly documents what `/vd-arch-review` does NOT do:
- Not an architect replacement
- Not a refactor tool
- Not a test runner
- Not a security audit
- Not a runtime profiler
- Not a pentest

### Relationship to other skills

| Skill | Focus | Trigger | Audience |
|---|---|---|---|
| **VibeDev** | Project governance | User-invoked | Leigos + devs |
| **VibeShield** (`audit`) | Security C1-C8 | Auto via G1-G7 | Devs |
| **VibeShield** (`code-review`) | Per-PR Standards + Spec | User-invoked | Devs |
| **`/vd-arch-review`** | Architecture, debt | User-invoked | Devs (only) |

All four are complementary. None replaces the others.

### Backward compatibility

- 12th command is **purely additive**. Existing 11 commands unchanged.
- Does NOT write to `PROJECT_STATE.md` (project state owned by VibeDev)
- Does NOT activate layman mode (dev-only)
- Does NOT auto-trigger from VibeShield (architectural review is human decision)
